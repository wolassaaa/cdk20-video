事件表格式（events/<段>.json）

HKBU SCIE1007 课程作业的科普视频。这一页说明"词 → 画面事件"表怎么写。表只写"哪个东西、做什么、从哪个词起、到哪个词停"，不写帧号。帧号由 resolve.py 按总表（master_v1.json，录音实测的词时间）算出来，写到 keys/<段>.json。

文件

  • 一段一个文件：映射/events/<段>.json。出镜对话组的文件名把 + 换成 _，例如 1-05_1-06_1-07.json。
  • 顶层字段：schema（固定 cdk20.events/1）、group（段号）、tool（blender / remotion）、note、holds（有意停住的段内帧区间，可空）、events（列表）。

一个事件

{"id": "bill0", "obj": "bill_0", "verb": "eject",
 "at": {"word": "cost", "off": 0}, "lead": 60,
 "until": {"dur": 0}, "ease": "out", "means": "cost：第 1 张钞票顶出落下"}
字段 必填 含义
id 是 段内唯一，程序用它取帧
obj 是 动的东西（Blender 物体名或 Remotion 图层名）
verb 是 flow / grow / eject / retract / appear / move / camera_to 七个之一
at 是 落点，也就是这个词说出口、东西到位的那一刻。{"word": 词, "off": 偏移帧}；词可以写 wid（1-08.w018）、原词（cost）或第几次（and#2）。也可以写 {"event": 前面某个事件的 id, "off": n}，跟在前一个事件后面
lead 否 落点前提前多少帧起动，默认 0
until 否 动作持续到哪里。{"word": 词} 是那个词说完，加 "edge": "start" 就改成那个词开口；{"sentence_end": true} 到本句句尾，也可以写句号 "1-08.s3"；{"dur": 帧数} 从落点起算持续多少帧；{"event": id} 和那个事件同时结束。都可以带 off。不写就在落点结束
ease 否 linear / in / out / inout / hold，默认 inout
means 否 一句话说明它在讲什么，给人看
seg 否 多段组里只在这一段找词

算出的帧：f_land = 词开口帧 + off，f_start = f_land − lead，f_end 由 until 决定。三个都是段内 60 fps 帧。keys/ 里另给片内帧 F_* = 段在片里的起点帧 + f_*。

规则（validate_events.py 检查）

  1. 格式：id 唯一，verb 和 ease 只能用上表里的值。
  2. 引用的词在总表这段里存在。
  3. 顺序：f_start ≤ f_land ≤ f_end，都在段内；until 不能早于 at；at.event 只能引用写在前面的事件。
  4. 每句说话期间，没有任何事件在动的时间不超过 90 帧（1.5 s）。
  5. 每句最后一个事件结束不早于句尾前 2 帧（动作不早停）。

迁移来的表

migrate_beats_v8.py 自动写的表顶层带 "migrated": "migrate_beats_v8"。其中 obj: footage 的事件是旧动画的变速锚点：value=[源片起秒, 源片止秒]，意思是这段帧里播放源片的这一截。它们可以用来原生重渲旧动画，但不算语义事件，要按剧本补写"说到哪个词、哪个东西出现"。重新迁移不会覆盖没有这个标记的手写表。
