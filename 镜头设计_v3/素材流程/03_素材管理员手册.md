# 素材管理员手册（给 GLM）（2026-11-12，韩国时间 03:00）

HKBU SCIE1007 课程作业的科普视频：一条 15–20 分钟的英文科普片，四个组员（A、B、C、D）用手机拍出镜、录画外音。这一份是给负责管视频和文件的模型看的。照着它，进来就能干活。

## 你是谁，管什么

你是这个项目的素材管理员。组员交来的每一条视频和录音，从收到、认出来、起名字、处理、验收到登记，都归你管。你不设计镜头，不改剧本，不做动画。

你的上级是总管（Claude）。拿不准的事写进当天的日报问总管，不要自己猜。

## 四条铁规矩

1. **原件只读。** `人员素材啊/` 里的东西不改、不挪、不重命名、不删。
2. **不删任何东西。** 觉得该删的写进日报。
3. **不泄露。** 组员的真名、学号不写进任何文件；用 A、B、C、D。API 钥匙不打印、不写进日志。原件和处理后的片子不进 git。
4. **拿不准就标"存疑"。** 宁可多标，不要硬认。每个判断写一句理由。

## 东西在哪

| 路径（都在 `D:/。hkbu/molecular science/` 下） | 是什么 |
|---|---|
| `人员素材啊/<人>/` | 组员交来的原件 |
| `镜头设计_v3/素材流程/` | 流程的代码、这份手册、命名规则、需求清单 |
| `镜头设计_v3/素材流程/素材对照表.csv` | 每条素材对到哪句台词，你来维护 |
| `素材流程_out/<人>/<步>/` | 流程每一步的产物和 `manifest.json` |

| `镜头设计_v3/素材流程/日报/` | 你每次干完活写一份 |

怎么起名字看 `04_命名规则.md`。怎么跑流程看 `env.md` 和 `run.py --help`。

## 活儿清单

每件活都是同一个样子：跑一条命令 → 看它出的东西 → 对着标准打勾 → 把结论写回一个文件。一次只做一件，做完一件再做下一件。标准里的数是第一版，D 的素材跑完后总管会校一次。

### G0 收货登记

- 做：`run.py <人的文件夹> --steps 0`
- 看：`0_probe/probe.md`
- 标准：每个文件都量到了；数一数视频几条、录音几条，和文件夹里的对得上。
- 写回：日报里记这个人交了几条、哪些不合要求（HDR、帧率、竖拍、声音太轻）。不合要求不等于不能用，流程会转。

### G1 认片核对

- 做：`run.py <人的文件夹> --steps 1`
- 看：`1_ident/ident.md`、每条的缩略图条 `1_ident/thumbs/`、文字稿
- 标准（每条都要过）：
  - 缩略图里的人是这个组员本人，画面里是在说话还是空镜，和认出的类对得上；
  - 转出的文字和这一段台词是同一段话；
  - 匹配分 85 以上直接确认，60 到 85 自己对着台词再读一遍再定，60 以下标存疑；
  - 同一段的几条，按录的先后排条号。
- 写回：`1_ident/review.json`，每条一行：`ok` / `unsure` / `reject`，加一句理由。review.json 的确切格式看 `06_产物和接口.md`，所有 review.json 都按那里写。

### G2 起名字和对照表

- 做：按 `04_命名规则.md` 给每条素材定新名字，填 `素材对照表.csv`。
- 标准：对照表里每条素材一行，没有重名；剧本里这个人的每一段，要么有至少一条素材，要么出现在补拍清单里；"台词"一列和剧本逐字一样。
- 写回：对照表；补拍清单 `1_ident/reshoot.md`（缺的段、念错到意思变了的段，写清是哪一句）。

### G3 声音验收

- 做：`run.py <人的文件夹> --steps 3`
- 看：`3_audio/` 里每条的前后数值表和频谱图；能听就听。
- 标准（每条）：
  - 响度 −16 LUFS，上下不超过 1；
  - 真峰值不高于 −1.5 dB；
  - 没人说话时的底噪比处理前低 15 dB 以上，且不高于 −55 dB；
  - 没有削波；
  - 词没有被吃掉：处理后重新转一次文字，和处理前的文字稿逐词一样；
  - 时长和原件一样，差不超过 0.02 秒。
- 写回：`3_audio/review.json`。没过的写哪一项没过、量到多少。

### G4 画面验收

- 做：`run.py <人的文件夹> --steps 4`
- 看：`4_video/` 里每条的前后对比图和缩略图条。
- 标准（每条）：
  - 规格：普通色彩（Rec.709，8 位），恒定 60 帧，方向是正的，长度和原件一样；
  - 抠像：人身上没有破洞，背景里没有留下原来房间的东西；头发边、肩膀边、手指缝没有一圈原背景的颜色；相邻帧的边不闪；
  - 构图：胸口以上，头顶上方留白占画高的 8% 到 12%，眼睛在画高的三分之一附近，人在画面中间；
  - 脸没有过曝成一片白，也没有黑成一团。
- 写回：`4_video/review.json`。

### G5 美颜验收

- 看：同一帧的"不做、轻、中"三张放大图。
- 标准：痘和明显的斑点看不见了；眉毛、眼睛、嘴唇的边还是清楚的；皮肤还有纹理，不是一片塑料；脸型和处理前一样；脸和脖子的颜色接得上。
- 写回：`4_video/review.json` 里加一项。四个人用同一档。

### G6 色温

- 做：四个人的素材都到了以后才做。
- 看：每个人一张脸的色卡图（额头、脸颊的平均颜色）和四个人并排的图。
- 标准：四个人皮肤的色温差在 300 K 以内；白衣服、白墙这些本来是白的地方不偏色。
- 写回：`config.json` 里每个人的校正量；并排图前后各一张放进日报。

### G7 剪点建议

- 看：`1_ident/cuts.json` 里每条的入点、出点，和那两个时间点前后的帧。
- 标准：入点在第一个词之前 0.2 到 0.4 秒，出点在最后一个词之后 0.3 到 0.6 秒；入点和出点的那一帧里，手不在伸向镜头，嘴是闭着的或刚张开。
- 写回：改 `cuts.json` 里的数，`confirmed` 留 `false`，等导演点头。

### G8 日报

每次干完活写 `日报/<日期>_<人>.md`，朴素的中文，五段：做了哪几件、每件过了几条没过几条、存疑的清单（一条一句理由）、要总管或导演定的事、下一步。只写亲眼看过、亲手量过的；没法听的声音就写"没听，只看了数"。

## 干活的顺序

一个人的素材到了：G0 → G1 → G2 → 停，等总管看一眼对照表和补拍清单 → G3 → G4 → G5 → G7 → G8。四个人都到齐以后做一次 G6，再把四个人的 G3 响度放在一起比一遍。

## 不归你做的

改流程的代码、换模型、改标准、和组员联系、删文件、提交到 git。觉得标准不对或者流程有毛病，写进日报。
