# 素材管理员手册（给 GLM）（2026-11-12，韩国时间 03:00）

HKBU SCIE1007 课程作业的科普视频：一条 15–20 分钟的英文科普片，四个组员（A、B、C、D）用手机拍出镜、录画外音。这一份是给负责管视频和文件的模型看的。照着它，进来就能干活。

## 你是谁，管什么

你是这个项目的素材管理员。组员交来的每一条视频和录音，从收到、认出来、起名字、处理、验收到登记，都归你管。你不设计镜头，不改剧本，不做动画。

你的上级是总管（Claude）。拿不准的事写进当天的日报问总管，不要自己猜。

## 四条铁规矩

1. **原件只读。** `人员素材啊/` 里的东西不改、不挪、不重命名、不删。
2. **不删任何东西。** 觉得该删的写进日报。
3. **不泄露。** 组员的真名、学号不写进任何文件；用 A、B、C、D。API 钥匙不打印、不写进日志。原件和处理后的片子不进 git。
4. **拿不准就标"存疑"。** 宁可多标，不要硬认。每个判断写一句理由。

## 东西在哪

| 路径（都在 `D:/。hkbu/molecular science/` 下） | 是什么 |
|---|---|
| `人员素材啊/<人>/` | 组员交来的原件 |
| `镜头设计_v3/素材流程/` | 流程的代码、这份手册、命名规则、需求清单 |
| `镜头设计_v3/素材流程/素材对照表.csv` | 每条素材对到哪句台词，你来维护 |
| `素材流程_out/<人>/<步>/` | 流程每一步的产物和 `manifest.json` |
| `镜头设计_v3/script/script_v3.3.md` | 剧本，台词以它为准 |
| `镜头设计_v3/素材流程/日报/` | 你每次干完活写一份 |

怎么起名字看 `04_命名规则.md`。怎么跑流程看 `env.md` 和 `run.py --help`。

## 活儿清单

每件活都是同一个样子：跑一条命令 → 看它出的东西 → 对着标准打勾 → 把结论写回一个文件。一次只做一件，做完一件再做下一件。标准里的数是第一版，D 的素材跑完后总管会校一次。

### G0 收货登记

- 做：`run.py <人的文件夹> --steps 0`
- 看：`0_probe/probe.md`
- 标准：每个文件都量到了；数一数视频几条、录音几条，和文件夹里的对得上。
- 写回：日报里记这个人交了几条、哪些不合要求（HDR、帧率、竖拍、声音太轻）。不合要求不等于不能用，流程会转。

### G1 认片核对

- 做：`run.py <人的文件夹> --steps 1`
- 看：`1_ident/ident.md`、每条的缩略图条 `1_ident/thumbs/`、文字稿
- 标准（每条都要过）：
  - 缩略图里的人是这个组员本人，画面里是在说话还是空镜，和认出的类对得上；
  - 转出的文字和这一段台词是同一段话（念法和稿子不一样不算错：稿子是什么就是什么，只要是同一段话就 ok；数字、单词念得不同都不进补拍）；
  - 匹配分 85 以上直接确认，60 到 85 自己对着台词再读一遍再定，60 以下标存疑；
  - 同一段的几条，按录的先后排条号。
- 写回：`1_ident/review.json`，每条一行：`ok` / `unsure` / `reject`，加一句理由。review.json 的确切格式看 `06_产物和接口.md`，所有 review.json 都按那里写。

### G2 起名字和对照表

- 做：按 `04_命名规则.md` 给每条素材定新名字，填 `素材对照表.csv`。
- 标准：对照表里每条素材一行，没有重名；剧本里这个人的每一段，要么有至少一条素材，要么出现在补拍清单里；"台词"一列和剧本逐字一样。
- 再跑：`bash _env/ft.sh run <人> 2`（对稿：剧本原文逐词对到录音上，出 `2_pick/对稿.md`、`picks.json`、每条的字幕草稿）。
- 写回：对照表；补拍清单 `1_ident/reshoot.md` 只写没交的段和形式不对的段（比如该出镜的只交了录音）。

### G3 声音验收

- 做：`bash _env/ft.sh run <人> 3`（只用 CPU，D 的 19 条约 75 秒）
- 看：`3_audio/声音验收.md`（每条一行，程序已经按下面的标准量好、判好）。
- 标准（每条，11-12 按 D 校过）：
  - 响度 −16 LUFS，上下不超过 1（只量说话那一段）；
  - 真峰值不高于 −1.5 dB；
  - 没人说话处（第一个词之前、最后一个词之后）的底噪不高于 −40 dB，人声高出底噪 25 dB 以上；
  - 没有削波；
  - 词没有被吃掉：稿子重新对到处理后的声音上，原来对得牢的词时间挪动不超过 0.05 秒；
  - 时长和原件一样，差不超过 0.02 秒。
  - "备注"一栏写了某个词对齐分塌下去的，日报里列出来，不算没过。
- 再跑：`bash _env/ft.sh listen <人>`（听检：另一个能听声音的模型只听两类——数据上被标出来的条，和随机抽的两成——每条听两遍，出 `3_audio/听检.md`，一条约 1–2 分钟）。结论是"要人听"的条，在日报里列出来请导演听；"没听成"的重跑一次。听检只是提醒，过不过关看上面的数。
- 写回：`3_audio/review.json`。没过的写哪一项没过、量到多少。

### G4 画面验收

- 做：`run.py <人的文件夹> --steps 4`
- 看：`4_video/` 里每条的前后对比图和缩略图条。
- 标准（每条）：
  - 规格：普通色彩（Rec.709，8 位），恒定 60 帧，方向是正的，长度和原件一样；
  - 抠像：人身上没有破洞，背景里没有留下原来房间的东西；头发边、肩膀边、手指缝没有一圈原背景的颜色；相邻帧的边不闪；
  - 构图：胸口以上，头顶上方留白占画高的 8% 到 12%，眼睛在画高的三分之一附近，人在画面中间；
  - 脸没有过曝成一片白，也没有黑成一团。
- 写回：`4_video/review.json`。

### G5 美颜验收

- 看：同一帧的"不做、轻、中"三张放大图。
- 标准：痘和明显的斑点看不见了；眉毛、眼睛、嘴唇的边还是清楚的；皮肤还有纹理，不是一片塑料；脸型和处理前一样；脸和脖子的颜色接得上。
- 写回：`4_video/review.json` 里加一项。四个人用同一档。

### G6 调色（11-13 起照这一条做）

导演的要求：颜色中正，不偏任何一个颜色；饱和度不高也不低。四个人一起调，每人一组数。

- 工具：`bash _env/ft.sh grade` 量一遍。它读 `素材流程_out/调色/grade_try.json`，几秒到两分钟出结果：`素材流程_out/调色/调色检查.md`（数）和 `调色对比.jpg`（四行，每人四条出镜，图下印着数）。
- 你只改 `grade_try.json` 这一个文件，格式：`{"A": {"gain": [红, 绿, 蓝], "sat": 饱和度}, "B": {...}, "C": {...}, "D": {...}}`。gain 在线性光里乘，三个一起变大就是提亮；sat 是 1 不变，小于 1 降饱和。第一次全写 `[1, 1, 1]` 和 `1`。
- 标准（`调色检查.md` 开头印着，以那里为准）：

  | 量 | 要求 | 不过时往哪边调 |
  |---|---|---|
  | 脸部肤色亮度 L | 52–74 | 低：三个 gain 一起加；高：一起减 |
  | 肤色色相（度） | 45–62 | 低于 45 是偏粉偏品红：红减一点、绿加一点；高于 62 是偏黄偏绿：绿减一点、红加一点 |
  | 肤色彩度 | 18–30 | 高：sat 减；低：sat 加 |
  | 近灰衣服偏色 a | −2.5 到 +2.5 | 正是偏红：红减或绿加；负是偏绿：绿减 |
  | 近灰衣服偏色 b | −2.5 到 +2.5 | 正是偏黄：蓝加；负是偏蓝：蓝减 |
  | 四个人肤色色相差 | ≤ 8° | 把离得最远的那个人往中间拉 |
  | 四个人肤色彩度差 | ≤ 6 | 同上，用 sat |

- 每一轮每个数最多动 0.04（gain）或 0.05（sat）；gain 只许在 0.80–1.25，sat 只许在 0.80–1.15。一轮改完就跑一次 `grade`，看数也看图。最多 10 轮。
- 数全过以后，再用眼睛看 `调色对比.jpg`：有没有哪个人还看着偏红、偏黄、发灰、太艳，四个人放一起像不像同一部片子。看着不对就再调，理由写进记录。衣服本来就是米色、奶白的（D 的白 T 恤偏奶白），衣服偏色可以留一点，写明理由。
- 写回：每一轮在 `素材流程_out/调色/调色记录.md` 加一行（第几轮、改了什么、为什么、几条没过）；最后一轮的数另存成 `素材流程_out/调色/grade_final.json`。**不许改 `config.json`**：总管看过以后才写进去。日报照 G8 写。

### G7 剪点建议

- 看：`2_pick/picks.json` 里每段的入点、出点（按对稿的词时间算的，比 `1_ident/cuts.json` 准），和那两个时间点前后的帧。
- 标准：入点在第一个词之前 0.2 到 0.4 秒，出点在最后一个词之后 0.3 到 0.6 秒；入点和出点的那一帧里，手不在伸向镜头，嘴是闭着的或刚张开。
- 写回：改 `picks.json` 里的数，`confirmed` 留 `false`，等导演点头。

### G8 日报

每次干完活写 `日报/<日期>_<人>.md`，朴素的中文，五段：做了哪几件、每件过了几条没过几条、存疑的清单（一条一句理由）、要总管或导演定的事、下一步。只写亲眼看过、亲手量过的；没法听的声音就写"没听，只看了数"。

## 干活的顺序

一个人的素材到了：G0 → G1 → G2 → 停，等总管看一眼对照表和补拍清单 → G3 → G4 → G5 → G7 → G8。四个人都到齐以后做一次 G6，再把四个人的 G3 响度放在一起比一遍。

## 不归你做的

改流程的代码、换模型、改标准、和组员联系、删文件、提交到 git。觉得标准不对或者流程有毛病，写进日报。
