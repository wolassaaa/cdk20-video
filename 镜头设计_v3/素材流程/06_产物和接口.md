# 流程的产物和文件格式（2026-11-12，韩国时间 12:10）

HKBU SCIE1007 课程作业的科普视频。这一份列每一步写出什么文件、格式是什么、谁读它。路径都在 `素材流程_out/<人>/` 下。手册 `03_素材管理员手册.md` 里提到的文件名以这里为准。

## 入口

```
_env/footage/Scripts/python.exe 镜头设计_v3/素材流程/run.py 人员素材啊/D [--steps 0,1] [--force]
```

每步写 `manifest.json`（读了哪些文件和它们的大小、修改时间，参数，产物，用时）；输入和 `config.json` 里这一步的参数没变就跳过。

## 第 2 步 `2_pick/`（选条、对稿）

**稿子是什么，字幕和对照就是什么。** 把剧本这一段的原文逐词强制对齐到录音上（torchaudio MMS_FA），识别出来的字只作参考。D 的 18 条实测：对齐的第一个词离声音真正起来的地方中位 0.03 秒，识别的词时间早约 0.2 秒。

| 文件 | 内容 | 谁读 |
|---|---|---|
| `align/<新名字>.json` | 剧本原文逐词：`{"w","t0","t1","score","heard"}`，时间是原件里的秒；`heard` 是识别在这个时间听到的，只作参考；`weak_words` 是对得不牢的词（score < 0.35，可能没念或念成别的，只影响那个词的时间） | 字幕、第 5 步 |
| `align/<新名字>.srt` | 稿子原文的字幕草稿，按标点和 42 个字符断行，时间是原件里的秒 | 剪辑 |
| `picks.json` | 每段建议用的条和剪点（第一个词前 0.3 秒、最后一个词后 0.45 秒）：`{"beat","pick","others","in","out","confirmed": false}` | 管理员 G7、导演、第 5 步 |
| `对稿.md` | 每条：第一个、最后一个词，建议剪点，念的时长和剧本时长，弱的词 | 人看 |

## 第 3 步 `3_audio/`（声音，只用 CPU）

整条原声 → 有削波的先 adeclip → DeepFilterNet3（最多压 18 dB，没人说话处留一层很轻的房间底；底噪还超标的再多压 6 dB 重做一次）→ 按说话那一段的响度定一个增益 → 4 倍过采样的真峰值限制，响度不够再补一次。

| 文件 | 内容 | 谁读 |
|---|---|---|
| `<新名字>_aud.wav` | 48 kHz 24 位单声道，和原件一样长，时间点和原件一一对应（第 2 步的词时间、剪点直接能用） | 第 5 步 |
| `results.json` | 每条：增益、前后响度、真峰值、底噪、削波、时长差、词的时间挪动、对齐分前后、没过的项 | 第 6 步 |
| `声音验收.md` | 同上，一条一行，给人看 | 管理员 G3 |

### `review.json` 的格式

```json
{
 "person": "D",
 "reviewer": "GLM glm-5.3-flash",
 "made": "2026-11-12 13:00 韩国时间",
 "items": [
  {"name": "D_cam_1-05_t1", "verdict": "ok",     "reason": "缩略图是 D 本人在说话，文字和 1-05 台词一致，100 分"},
  {"name": "D_cam_3-06_t1", "verdict": "unsure", "reason": "开头少了 So，念成 a really strong suspect，意思没变，要导演定"},
  {"name": "D_ext_x02_t1",  "verdict": "reject", "reason": "低头写字的空镜，不是剧本段，片尾也用不上"}
 ]
}
```

- `verdict` 只能是 `ok` / `unsure` / `reject`；`reason` 一句话。
- `name` 必须和 `library.json` 里的一致。没写到的素材按 `unsure` 算。
- 第 2 步选条只在 `ok` 的里面排；`reject` 的不进后面的步骤；`unsure` 的列给导演。
