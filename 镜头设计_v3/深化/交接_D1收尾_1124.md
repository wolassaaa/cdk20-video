## 出片后做的事（全部在项目根目录，bash）
1. 看队列：`PYTHONIOENCODING=utf-8 python _env/queue/qctl.py list | grep d1c_`。failed 的看 `_env/queue/logs/d1c_<段>.log`，修好后 `qctl.py retry d1c_<段>`（可重跑）。
2. 每段的机检结果在 `G:/cdk20/work/oncam/<段>/flaws.json`，改前的在同目录 `flaws_before_d1.json`。验收：除 M10 外，改前通过的项改后不许变差；M10 要在 0.25–1.1。也可单独重跑：`cd 镜头设计_v3/inserts && PYTHONIOENCODING=utf-8 python oncam_check.py <段>`。
3. 帧数必须和旧片一样：`d1_page.py` 会把每段新旧帧数写在第一列（`旧 → 新`），不一致的补跑那段合成。
4. 生成对照页：`cd 镜头设计_v3/inserts && PYTHONIOENCODING=utf-8 python d1_page.py`，输出 `导演检查_20261123/32_出镜颗粒返修_对照.html`（每段脸和背景墙 400×400，改前/改后同一帧，加 M10 前后、机检通过数前后、变差项红字）。18 段都出完再跑。
5. 有变差的段：看 flaws.json 那一项，若是人像增强引起（如 M8 抠像漏块、M9 亮度跳变），把该段在 `SEGS` 里加 `PERSON_DN`/`PERSON_SH` 的段内覆盖，或用环境变量 `ONCAM_DN=0 ONCAM_SH=0` 重跑该段。
6. 收尾：`镜头设计_v3/工作记录.md` 末尾追加一行（工具：shot_oncam comp + libx264；设备 CPU；各段用时看 `G:/cdk20/work/oncam/<段>/comp.json` 的 sec）；`镜头设计_v3/打磨清单.md` 的 D1 状态改成"已修（rc 待拼）"。
7. 新片给粗剪拼装用（manifest 里的路径不变，原名原目录）。旧 `_g1` 片留着，不删。
