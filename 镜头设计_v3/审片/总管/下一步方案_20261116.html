2. 全片按词对时

2.1 变速还是重渲：判定阈值（机器判）

对每段按 对时/anchors.py 的办法量锚点（画面事件 src 秒 → 词的粗剪秒），算相邻锚点之间的倍速，然后按下面判，retime_check.py 直接输出 "变速 / 重渲 / Remotion 重出"：

条件 判定
段是 Remotion 矢量（S1S2 平面、S6 后半、S7/S8、所有数据卡） 一律从节拍表重出，不变速（CPU，便宜，没有补帧问题）
任一对锚点先后和台词相反 重渲
任一倍速 < 0.5 或 > 2.0 重渲
相机在动的区间倍速在 0.75–1.35 以外 重渲（移镜忽快忽慢最显眼）
相机不动的区间倍速在 0.6–1.6 以外的超过 1/3 重渲
对时后任一 1.5 秒窗口里没有落在词上的动作（含最后一个词到声音完） 重渲或补动作（没有东西可拉）
以上都不中 变速（甲档），trial.py 那套；尾部多余画面裁掉，末帧不停

1080p30 交片，源是 60 fps，0.5× 以上不补帧。变速过的段在交片单里记倍速表，4K 阶段（导演批后）凡 < 1.0× 的按同一节拍表重出。

2.2 节拍表格式（一段一份 JSON，Blender 和 Remotion 读同一份）

镜头设计_v3/对时/beats/<段号>.json
{
 "seg": "5-03", "fps": 60, "speaker": "C",
 "audio": {"take": "C_vo_5-03_t1", "head": 0.15, "tail": 0.25, "speech_from": null},
 "words": [{"w": "001's", "t0": 0.60, "t1": 0.92}, ...],          // 由 resolve 写入，已换算成段内秒
 "frames": {"len": 1015, "first_word": 9, "last_word_end": 1000},  // 由 resolve 写入
 "events": [
  {"id": "card_up",  "word": "001's", "lead": 10, "dur": 14, "verb": "升", "obj": "card_001", "p": {"dz": 0.06}},
  {"id": "cam_pocket","word": "micromolar.", "lead": 0, "dur": 180, "verb": "cam", "to": "pocket_001"},
  {"id": "kd_card",  "word": "9.2", "lead": 6, "dur": 20, "layer": "remotion", "text": "Kd = 9.2 ± 0.5 µM (n = 3)", "pos": "tl"},
  ...
 ],
 "handoff": {"in": "push_from_5-02", "out": "pull_to_5-04", "frames_in": 24, "frames_out": 24}
}
  • word 是词的原文（同一词出现多次写 "word": "30.#2"）；lead 是提前起动的帧数（6–16，相机 0）；落点帧 = 词 t0 的帧。无台词的事件写 "after": "<id>", "gap": 帧。
  • 动词只用托盘方向稿的 12 个安全动词加 cam、text；obj 是场景里的物件名，路径由代码按几何定，不许穿模。
  • resolve 步骤：beats_resolve.py <段号> 读 place.json，用 build_cut.condense 同一函数算头尾和压停顿后的词时间，写回 words 和 frames，并给每个 event 算出 f_start、f_land。声音一改就重跑，改了帧的段才重渲（按 frames 和 events 的哈希比对）。
  • 机器检查在 resolve 时就做：任意 90 帧窗口没有 f_land → 报错；两个事件 f_land 相差 < 6 帧且不是同一主体 → 报错；last_word_end 之后没有事件 → 报错。

2.3 Blender 和 Remotion 怎么读

  • Blender：bl_inserts.py 加环境变量 BEATS=<json>；各 shot_* 里现在的 upd(T + 秒) 和 META 时长改成 B.f("word") 和 B.len。关键帧插入统一经一个 at_word(obj, word, lead, dur, fn) 小函数。先改第 5 章五段，再改 S1 的 a w b、f 两组插镜，其余按 2.1 判出来的重渲清单逐个改。
  • Remotion：entry.jsx 等的 at={秒} 改成 at={B("5-03","9.2")}，B 从 对时/beats/*.json 读；S1S2 的 s1_timeline.json 不再从 节奏表.csv 生成，而是从节拍表生成（timeline.py 加一个输入）。
  • 拼片：build_cut.py 读同一批节拍表取每段长度，声音仍按毫秒；接点帧数从 handoff 取。

2.4 顺序和工作量

全片约 45 个画外音段。S1 六段已量；第 5 章五段这次直接做节拍表；其余 34 段量锚点每段 20 分钟（抽帧和字区实测可交 GLM，我抽查），约 11 小时 CPU 时间，和显卡渲染并行做。按 S1 比例约一半要重渲，三维台面段在 S3、S4、S6 前半、S7，估 10–14 段，每段 600–1500 帧，共约 1.2 万帧，两路 1080p 16 采样约 2 小时显卡。

3.3 批量做法和检查

  • 每段：beats_resolve → Blender 两路（gpu_slot.sh，每块 ≤ 60 帧）→ TRAY_TRACK 出锚点和穿模 → Remotion 叠批注 → tray/check.py（已有，扩成通用）。
  • 过关（机器）：落点差 |land − word| ≤ 3 帧；max_object_gap ≤ 90 帧；x < 860 没有物体；穿模帧 0；最小亮度不低于纸底的 0.35（3-09 例外只暗托盘）；人完全露出到首词 ≥ 6 帧；末词结束到转场起点 ≥ 4 帧；接点两侧帧差（check.py 的 join_diff）≤ 8；文字 ≥ 56 px；字幕区 y > 930 无物体。
  • 渲染量：28 段约 170 秒 ≈ 1 万帧，托盘区 1080p 16 采样每帧约 0.5 秒（试片 v2 实测 32 采样两路 576 帧 9 分钟），两路约 1.5 小时，加场景搭建开销约 2.5 小时。
