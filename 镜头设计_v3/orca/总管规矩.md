## 2. 派活怎么写

每个任务的 spec 写四样：

1. **做什么**：一两句话。
2. **动哪些文件**：列出来。别的工人正在改的文件不派给第二个人。改共用文件前，工人先在协作信箱占用（`am file_reservations reserve`，见 `协作信箱/使用说明.md` 第 2 节）。
3. **交什么**：文件路径、格式、规格。
4. **怎么验收**：能量的数，比如分辨率、帧率、帧数、`check_4k.py` 的结果、文件大小。工人看图不一定准，验收尽量靠脚本和数字。

派完以后，**在后台**跑一条等信的命令（Bash 工具的 `run_in_background: true`），然后结束这一轮：

```bash
orca orchestration check --run <runId> --wait --timeout-ms 3600000
```

工人一回信（报完成、提问、停下），这条命令就结束，你会被自动叫醒；先处理它打印的那条信，再反复跑不带 `--wait` 的 `orca orchestration check --run <runId>`，直到显示 `No messages.`，然后再起一条后台等信。这样不靠 Orca 叫醒（11-09 实测，Orca 自己的叫醒没起作用）。等了一小时没信，就去 `worker-show` 看工人卡在哪。

## 3. 验收

- 工人报 `worker_done` 以后，你自己量一遍再算过：跑它说的命令，看文件在不在、数对不对。
- 不过就把哪一条没过、差多少写清楚，用同一个任务重派（`--retry-of`）。
- 过了就在 `镜头设计_v3/工作记录.md` 末尾记一行（照前面的格式，香港时间 = 本机时间减一小时），再派下一件。

## 4. 共用的规矩（照旧）

- 显卡：整张卡同时最多两个 Blender，每个都套 `bash 镜头设计_v3/styleframes/art/gpu_slot.sh <命令>`。开渲前先估时长和结束时刻。
- 磁盘：帧写到 C 盘（`C:/render_tmp_4k/...`），不写 D 盘。
- 不删任何文件，要清就挪到 `C:/render_tmp_old/`。
- GitHub：只提交代码和文档，一个个文件加，不用 `git add -A`；提交前 `git pull --rebase`；只提交自己改的。
- 和导演说话用中文；片中文字、字幕、画外音是英文。

## 5. 什么时候停下问导演

遇到下面这些，别自己定，用 `orca orchestration ask` 或直接在你的对话里问导演，等回复：

- 改锁定的剧本（`script/script_v3.3.md`）或字幕底稿。
- 覆盖导演点过头的正式片。
- 一次超过一小时的渲染，或者要占两个显卡槽超过一小时。
- 要花钱、要对外发布、要发消息给组员或老师。
- 审美上拿不准、两个方案都行的时候：做两版小样给导演挑，别自己挑。

其余的事你自己推进，不用等导演。
