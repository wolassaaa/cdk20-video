# S1 按录音重新对时：方案

HKBU SCIE1007 课程作业的科普视频（英文）。这一步是剪辑对时的试点：S1 的动画是录音前按剧本估的时长做的，粗剪只对齐了段头，画面普遍抢在词前面。这里给出两档改法、工作量和推荐。量出来的数见 `S1_锚点表.md`，给程序用的数据是 `S1_锚点.json`。

规则（导演已定）：以录音为准，每个画面动作落在说到它的词上；声音的空白、长停顿和画面都能裁；不许末帧停住补时长。

## 偏差有多大

- 60 个动作，平均 −2.0 秒（画面早），绝对值平均 2.3 秒，18 个超过 3 秒，最大 −9.2 秒。
- 最差的三段：1-10（平均 −3.8，CDK20 模型比 "AlphaFold" 早 8.8 秒长出来，画面在 107 秒就演完，后面 7.5 秒没有新东西）；1-09（−3.5，站名一个比一个早，到 Approval 早 6.0 秒，最后末帧停 4.3 秒）；1-04（−2.0，药瓶和两个药名早 2–5 秒）。
- 1-08 基本对上（+0.2）。1-02、1-11 早 1.5 秒左右，主要是段中间某几件事挤在一起。
- 毛病分两种：
  1. **整体太快**（1-09、1-11）：动作先后和台词一致，只是间隔太短。分段变速就能对上，速度都在 0.5–1.1。
  2. **几件事挤在一起或先后反了**（1-02 的 Top 3 / lung·colorectal·liver 在 0.2 秒内先后出现，台词隔了 3 秒；1-04 Nexavar 字和药片在同一秒；1-10 Nobel、2024、AlphaFold 的先后和台词相反）：变速会出现 0.05×、8× 这种速度，或者根本对不上，只能改动画本身。

## 甲：不重渲，分段变速

做法：每段取锚点（画面 src 秒 → 词的粗剪秒），相邻锚点之间匀速；段头从这段画面开头起，最后一个锚点之后按 1.0× 放到声音完 +0.25 秒，多余画面裁掉。程序是 `trial.py`（读 `S1_锚点.json`，可以按序号去掉个别锚点）。

每段速度表（完整的在 `S1_锚点表.md` 每段末行和 JSON 的 `retime`；<0.6× 或 >1.6× 标出）：

| 段 | 分段速度（按时间先后） | 超界段数 | 结论 |
|---|---|---|---|
| 1-02 | 3.3, 1.4, **0.36**, **0.42**, **2.5**, **0.05**, 1.5, 1.3, **0.45**, **11.8**, **0.22** | 8/11 | 不能直接用。Top 3 和 lung… 两行字之间只有 0.2 秒画面，要撑 3 秒 |
| 1-04 | 1.4, **0.09**, **3.7**, **0.17**, **0.29**, 1.1, 1.56, **8.0**, 1.2, **3.6**, 0.7, 0.85, 1.0 | 6/13 | 不能直接用。药片、Nexavar 字、落瓶挤在 3 秒内，台词铺了 8 秒 |
| 1-08 | **0.17**（纸卡那 4 秒，另一人在删，裁掉即可）, **6.3**, 1.2, **0.34**, 0.7, 1.0, **1.75**, **1.67**, 1.0 | 5/9 | 本来就对上了，不用变速；只处理纸卡空出的 4 秒 |
| 1-09 | 3.0（只有 0.15 秒）, 0.62, 1.09, **0.49**, 0.87, 0.62, 0.65, 0.71, 0.93, 1.06, 1.0，后面 1.7 秒裁掉 | 1/11 有效 | **能用**，试片就是这段 |
| 1-10 | **0.58**, **0.55**, 1.45, **0.30**, 1.0，后面裁 5.3 秒 | 3/5 | 先后相反，只能对上 Nobel 一组；AlphaFold 仍早 9 秒 |
| 1-11 | **0.40**, 1.08, 1.0, **1.96**, 1.0 | 2/5 | 大体能用：开头地图停得久（0.4× 是地图静止，慢放看不出），Pak Shek Kok 那一下会快 |

补帧：交片是 4K60。慢于 1.0× 时 60 fps 就要重复帧或插帧；0.6–1.0× 重复帧轻微顿挫，台面 3D 镜头的缓慢平移最容易看出；<0.6× 必须补帧（ffmpeg minterpolate 在字和细线上会糊，不推荐）或重渲。粗剪 1080p30 用 60 fps 源，0.5× 以上不用补帧，试片就是这样出的。

工作量：S1 六段，量锚点和挑锚点各 20–30 分钟（大半已在这次做完），4K60 输出 2 分钟多的画面，NVENC 一次几分钟。S1 用甲做完约半天，但只有 1-09、1-11、1-08 能用这档交差。

## 乙：重渲

**Remotion 部分**：源码 `镜头设计_v2/tests/T4_remotion/src/v3/fusion/entry.jsx`（4K 成片用的是 `cut.sh` 生成的 `entry_cut.jsx`）。时间写在两处：

- `s1_timeline.json`：`TL.u[帧]` 把成片的每一帧换成"剧本时钟"秒，`TL.cam[帧]` 是全景相机位置。它由 `镜头设计_v3/styleframes/art/fusion/s1/code/timeline.py` 从同目录 `节奏表.csv` 生成。所有元素都按剧本时钟出场，所以**改 `节奏表.csv` 的时间对应（剧本秒 → 录音秒）就能整体对时**，相机路径跟着走，不用逐个改关键帧。这是乙档省事的地方。
- `entry.jsx` 里 129 处 `at={秒}`（S1 和 S2 合计），例如 `Any step can fail.` 在 241 行 `at={93.1}`，Nobel 在 248 行 `at={98.8}`，Sha Tin、Pak Shek Kok 在 458–459 行。挤在一起和先后相反的动作要逐个改这些数：S1 估计 25–35 处（1-02 约 6 处、1-04 约 6 处、1-10 约 8 处并把模型长出挪到 "AlphaFold" 之后、1-11 约 3 处）。

**Blender 插镜（`inserts/bl_inserts.py`）**：

| 镜头 | 片内秒 | 处理 |
|---|---|---|
| `a`、`w`、`b` 药板、落瓶 | 32.1–38.4 | 要重渲。药片顶破、落瓶和台词差 2–5 秒，而且要拉到约 0.6×，60 fps 下变速会顿；按新时间重排关键帧，约 380 帧 → 约 600 帧 |
| `c` 十个人立起躺下 | 43.35–48.5 | 只变速。速度 1.2、1.05 左右，可接受 |
| `f` 路线和玻璃泡 | 78.8–94.8 | 1080p30 只变速就行（试片证明）；4K60 交片要 0.5–0.9× 慢放，最好按新时间重渲（16 秒 → 约 21 秒，约 1300 帧）。站名是叠上去的字，跟 Remotion 走 |
| `g`、`h` | S2 | 不在本次范围 |

渲染时间（按 README 的 4K 实测：一帧 3.9 秒，两个 Blender 并行）：`a w b` 约 20 分钟，`f` 约 45 分钟；S1 的 Remotion 4K 约 25 分钟；拼接压片约 5 分钟。改时间、改 `at=`、核对约 3–4 小时。S1 用乙做完约一天（其中渲染约 1.5 小时）。**Blender 要在 RTX 5080 那台机器上跑**。

## 推荐

**甲为主、乙补漏**：

1. 先用甲把全片能变速对上的段一次做完（S1 里是 1-09、1-11；1-08 不动），粗剪马上能按录音看节奏。
2. 甲出现 <0.6× 或 >1.6×、或先后和台词相反的段，记进乙的清单，改 `节奏表.csv` 和 `at=` 重渲。S1 里是 1-02、1-04、1-10，外加 `a w b`、`f` 两组 Blender 镜头。
3. 交 4K60 前，甲做的段里凡有 <1.0× 的，也按同一锚点表重渲 Remotion（只改 `节奏表.csv`，便宜），避免 60 fps 下重复帧发顿。

理由：甲半天就能让导演看到 S1 对上录音的样子，而且锚点表就是乙要用的时间数据，不白做；只靠甲，S1 有一半的段会出现看得出的忽快忽慢；全部走乙，要 5080 渲染，又是逐段等审，慢。

时间估计：

- S1：甲半天，乙一天，合计约 1.5 天（含导演看一次）。
- 全片约 45 个非出镜段：量锚点每段 20–30 分钟（抽帧图、字区测量可交 GLM，我抽查），约 2–3 天；按 S1 的比例约一半段要进乙，重渲加改时间约 4–6 天，取决于 5080 能用多久。合计 1–1.5 周。

## `S1_锚点.json` 结构

```
{
 "note": "...",
 "segments": {
  "<段号>": {
   "new_start": 粗剪里这段开头（秒）,
   "src_start", "src_end": 这段在 S1S2_table_2.mp4 里的起止（秒）,
   "picture_end_cut": 粗剪里画面播完的时刻（此后是末帧停住；1-10 例外，被裁断）,
   "audio_first_word", "audio_end_cut": 首词开始、末词结束（粗剪秒）,
   "mean_offset", "mean_abs_offset", "max_offset": 偏差统计（秒，负 = 画面早）,
   "actions": [ {
     "action": 动作说明, "cut_t": 粗剪秒, "src_t": 源文件秒,
     "word": 对应的英文词（null = 无台词）, "word_t": 词开始的粗剪秒,
     "offset": cut_t − word_t, "anchor": 是否当变速锚点 } ],
   "retime": [ { "src0", "src1": 源秒区间, "out0", "out1": 对时后的粗剪秒区间,
                 "speed": 倍速, "flag": "慢…"/"快…"/"" } ],
   "tail_cut_src": 最后锚点之后裁掉的源秒数
  } } }
```

## 文件

- `words_in_cut.py` → `words_S1.json`：词时间换算到粗剪。
- `motion.py` → `motion_S1.npy`：粗剪前 140 秒帧差。
- `ink.py`：某区域字像素随时间变化，用来定文字出现。
- `anchors.py` → `S1_锚点.json`、`table.txt`（锚点表正文）。
- `trial.py <段> [去掉的锚点序号…]` → `试片/`。
- `_抽帧/`：每段每 0.5 秒的抽帧图和试片核对图，可删。

## 不确定的地方

- 动作对哪个词是按台词意思判断的，有几处可以有别的选法（如 1-02 肝静脉变蓝对 "not just us"、1-09 镜头升起对 "Any"）。导演或组员可以只看试片判断，不需要懂化学。
- 3D 镜头起落、液体流动的"开始"含糊 ±0.2 秒；文字类实测到 0.1 秒。
- 1-08 开头纸卡删掉后那 4 秒放什么，等另一人的版本；现按可裁处理。
- 1-10 的 AlphaFold 先后问题只有乙能解决，甲档里它仍早 9 秒。
- 4K 成片 `S1S2_table_2.mp4` 和粗剪底片 `rough_v0.mp4` 同一时间轴这一点，我按资源清单（文件内秒 = 剧本秒）算，试片抽帧对得上，没有逐帧比。
