# DS 工作规则（总管 BlueLake 写给 GreenCastle，11-09）

HKBU SCIE1007 课程作业的科普视频。导演 11-09 定了分工：BlueLake 当总管推进主线，你接 4-10、5-04、S5，外加总管派给你的活；专职复核员 SilverHawk 审你的片，审到全过；Codex（RedStone）管资源。这一份把你干活的规矩收在一处。和 `04_美术约束_v1.md`、`06_三维镜头细则.md` 冲突时，画面的事以 04、06 为准，流程的事以这一份为准。

## 1. 最要紧的一条：不靠看图，靠量

导演说你看图不一定可靠。所以你交出去的每一条"我做到了"，都要有一个**脚本跑出来的数或一行文字**作证，不写"看起来没问题"。

| 要确认的事 | 用什么查 | 写进交片信的样子 |
|---|---|---|
| 接头对上 | `check_4k.py <Blender 第0帧.png> --ref <上一段最后一帧.png>` | `joint 0.8 (<2)` |
| 规格、跳帧、太快、首尾静止 | `check_4k.py <审片片> --ref ...` | 照抄它的 4 行输出 |
| 机位、出画、压字、离台、朝向、变大小、移动 | `BL_CAMCHECK=6`（06 第 1 节） | `CAMCHECK flagged frames`、`big moves`、各类标记的秒数 |
| 穿模 | 你镜头里的 checks（06 第 7 节） | `clashes: none` |
| 右上标题格式 | `grep -n "y={92}" 镜头设计_v2/tests/T4_remotion/src/v3/fusion/s5.jsx`，每一行都要是 `fontSize={36}`、`Objective N / …`（11-09 查到 4-10 那两处还是 `fontSize={34}`、`Tool: docking / virtual screening`） | 贴那几行 |
| 批注颜色（红一屏一处） | `grep -n "<Note\|RED" 镜头设计_v2/tests/T4_remotion/src/v3/fusion/s5.jsx`，每个 `Note` 的颜色只能是 DARK 或 BLUE；`RED` 在一个镜头的同一时段只用一处 | 贴 grep 结果，标出那一处红 |
| 字体、字号、位置 | grep 字体名和 `fontSize`、`x`、`y`，对 04 第 5 节的表 | 贴对照 |
| 字不压东西 | 把 jsx 里每块字的框（x0,y0,x1,y1，1920×1080）写进 `BL_KEEPOUT` 再跑 `BL_CAMCHECK` | `in a text area: none` |
| 数字有出处 | 对照表里每个上屏数字有页码 | 对照表路径 |

**真要靠眼睛的事**（景别好不好、像不像钥匙、乱不乱），别自己猜，发信问 SilverHawk：写片名、第几秒、想确认什么，一封信只问一件事。例：`S4_410_3d_test_2.mp4 第 24 秒，7 把钥匙平躺后能不能一眼看出是钥匙？`

## 2. 总管派活怎么接

总管派活一律发信，信里有四样：**做什么、交什么（文件路径）、怎么验收（能量的数）、什么时候要**。你：

1. 收到先 `acknowledge_message`，回一句"收到，预计 HH:MM 交"（香港时间）。
2. 有看不懂的、做不到的，马上回信问，别猜着做。
3. 动共用文件前在信箱占用，做完释放。
4. 交的时候照第 1 节贴数，同一个 thread 回信。

导演直接跟你说的事，和总管信里的冲突时，以导演为准，回信告诉总管一声。

## 3. 文件

- **你自己的**：`inserts/bl_s5.py`、`inserts/take_s5.py`、`镜头设计_v2/tests/T4_remotion/src/v3/fusion/s5.jsx`、`styleframes/art/fusion/s4/` 下 4-10、5-04 的说明和对照表、你的审片片和静帧。不用占用。
- **共用的**（先占用）：`bl_inserts.py`、`check_4k.py`、`entry.jsx`、剧本、`00_下次开工.md`、`工作记录.md`（追加一行不用占）。
- **不删任何东西。** 旧版留着；要清地方，发信给 RedStone（资源管理），它挪到 `C:/render_tmp_old/`。
- **D 盘快满了**（11-09 13:50 只剩 5.5 GB）。渲染帧一律写 C 盘（`C:/render_tmp/...`，你现在就是这么做的），审片片才放项目里。
- 剧本是锁定的，不改；要改先写给导演（剧本原句、论文原文和页码、建议、字数变化）。

## 4. 显卡和电脑

- 显卡同时最多 2 个 Blender，算上总管的。开渲前在信箱 thread `GPU` 发信：做什么、几个槽、预计用时、结束时刻（香港时间），每个 Blender 套 `镜头设计_v3/styleframes/art/gpu_slot.sh`。
- `BL_CAMCHECK`、静帧草稿用 `BL_CPU=1`，不占显卡，但 CPU 和内存紧，同时只跑一个。
- 渲之前先估时长和结束时刻写在信里。

## 5. 时间、语言、记录、提交

- 本机时钟比香港快一小时。所有写下来的时间都是香港时间。
- 和导演、和总管、在信箱里都用中文；片中文字、字幕、画外音是英文。
- 每做完一步，`镜头设计_v3/工作记录.md` 末尾加一行，格式照前面，只写事实（时间、做了什么、工具、设备、用时、token）。
- 提交：只 `git add` 你自己的代码和文档，一个一个加，不 `git add -A`；不提交 mp4、png、pdf、歌。说明用中文。推送前 `git pull --rebase`，因为别人没提交的文件失败就直接推。

## 6. 内容边界

- 分子、数值、结论都来自论文，片中注明出处；不自己画分子结构，不让模型生成；上屏数字进对照表、带页码。
- 自己画的示意画面，出处行写 `Illustration ·`；预测的结构标 predicted。
- 不往组员那里派读结构、审对接姿势的活，组里没人能审。

## 7. 收信

- 每开始一步、每做完一步收一次信；没事做时 `/loop 30m` 收信。
- 复核员的意见每一轮都在 `05_审片意见.md` 和信里各一份，以表里"没过"的条目为准一条条改，改完在回信里逐条写"第 N 条：改了什么、现在量到多少"。
